# 新学科启动与持续练习：AI 自主执行 SOP（通用）

> 适用于新学科、新教材、新年级、新学期及已有学科的首次系统整理。不限数学、国語、中文或英语；各科保留自己的专项教学规则。本文是**AI 的工作指令**，不是要求家长逐步照做的教程。
>
> **触发语**示例：「我要开始【学科】」「帮我从头建立【学科】学习系统」「新学期【学科】该怎么做？」「我要开始一个新学科，你告诉我需要我做什么，其余你直接处理。」

## 总原则：收到启动请求就先行动

1. **先查再问**：立即读取本仓库 `SKILL.md`、对应的 `subjects/*.md`、`references/cloud-storage.md`，再检索当前账号有权限访问的私有 Library、现有学习记录、用户明确提供或此前已配置的 Google Drive 教材／作业文件夹。已知的年级、教材、学习者和目录不要再次询问。没有明确学科且确实无法推断时，只问「要启动哪门学科？」。
2. **主动完成可执行步骤**：发现文件、查看来源、建立或增量更新索引、校验、记录、补齐通用规则、制作可交付成果，在当前可用工具权限内直接执行，不把每一步改写成向家长的操作指令。不因为“将来可以使用 Work”就停止当前已经能够完成的工作。
3. **区分模型和权限**：大规模批量教材整理适合 Work，但 Chat 不能假装自己已经切换 Work 或启动另一工作空间。当前环境能访问并处理时直接完成；遇到只能由用户连接账户、上传文件、切换工作模式、授权的阻碍，才一次性说明**最少的一项必要操作**。不要许诺后台异步执行或未经证实的成功。
4. **隐私与职责分离**：教材知识、孩子真实掌握情况、日常作业是不同的数据。公开 GitHub 只存通用方法和不含隐私的科目规则；学习者身份、资料链接、逐题答卷、进度、索引保存在经授权的私有资料库。不要把“教材写过”判为“孩子已掌握”。

## 阶段 A：盘点新学科现状（收到触发语立即执行）

- 判明目标学科、教材版本、年级／册次、学习语言、此前是否已开始、当前可确认的学习进度，先用既有资料，不用长表格向家长索要。
- 只在目标学科范围内查找教材、已完成学校作业、测验、错题、既有知识索引、来源审计、`progress.md`、`study_log.md`、有效的专项科目规则及现有自动任务。
- 采用日方学年的默认换算（4月1日—次年3月31日），但遵守用户对学年、册次及“开始正式AI训练月份”的更具体配置；不凭文件上传时间推断教学日期。
- 已有同册知识索引时**先验证与增量补充**，不要重复创建平行索引、重置稳定ID、覆盖成绩或强制重新整理整册。
- 找不到材料时，先定位确实缺少的**一项关键条件**（如学科、教材链接或访问权限），询问一次；能用可靠现有资料继续的部分继续，不等待所有准备工作齐全。

## 阶段 B：建立知识索引（教材事实，不是能力评分）

1. 以真实教材和历史学校作业为依据，按章节／单元提取知识点、原语言术语、核心概念／语言能力、例题类型、练习范围、作答形式、前置能力、原始文件和印刷页码。
2. 用稳定且唯一的学科知识点ID，识别重复题型及交叉知识点，记录学校作业是否真的出现过；同一学科有多种教材体系时保留各自来源标签，不混淆出版社和教学顺序。
3. 为各知识点建立**教材／学校基础要求**；若适用数学L0阶梯，真实学校作业的题型、数字范围和步骤定义L0；如果学校作业缺失，注明「教材暂定，学校尚未验证」。其他学科按其专项文件定义基础能力，不硬套数学L等级或题量。
4. 将成果写入**私有 Library 的该学科目录**，推荐文件名 `<subject>_knowledge_index_<grade><volume>.md`、`<subject>_source_audit_<grade><volume>.md`。如果已有既定命名（如 `math_knowledge_index_2上.md`），**继续沿用既有文件名和目录**；尽量保持后续调用路径稳定。
5. 审计文件必须说明：实际检查文件数、覆盖单元与页码、可追溯引用、重复项、缺页、看不清及未验证范围。绝不声称完整检查未读取的原图。
6. 学科尚未有正式章节教材时，可基于已确认的作业、课程大纲、单词书或学过的文本建立**暂定索引**，明显标注依据和缺口，不捏造教材页码。

## 阶段 C：AI 复核与接入学习流程

1. 重新读取保存的索引和审计报告，检查稳定ID唯一性、来源引用与数量、知识粒度和覆盖边界；抽查适量**原始教材／学校作业**。发现不合理或不明确之处先修正、标注，不能为了完成流程而直接宣布全部正确。
2. 将**索引位置、检索顺序及使用边界**加入当前学科可用的 Skill 或自动任务。仅添加通用规则到公开仓库；真实儿童资料与私人链接不写 GitHub。
3. 学科专属要求优先：数学题型与5+5组成只属于已配置的数学系统；中文输入/口头平衡、日语国語和英语口语遵守各自规则，不机械把全部学科改成每天10道数学式题。
4. **接入不等于重新训练AI**：只配置在任务执行时读取哪个文件、如何依据索引挑选练习、如何把真实答卷写入动态进度。索引是“教了什么／基础要求”，进度是“孩子会到哪里”，分别维护。
5. 现有自动任务不得重复创建、删除或无指令改变时区／时间；**没有用户设定的调度意图，不擅自创建每日推送**。如果用户要求定时，则通过自动化工具真实创建／更新并验证启用状态。任务暂停时不能说它会照常自动运行。

## 阶段 D：立即交付可用结果，然后持续闭环

- 完成可行的准备后，给家长简短总结：找到哪些资料、已生成并保存哪些文件、已核验什么、接下来有哪些**只有人能做**的动作。能直接组织第一次练习／试测时，在符合已有约定或用户请求的条件下**直接生成**，不要再让家长逐项发指令。
- 以后按本学科已有规则检查近期作业，生成适合孩子年龄、目前学习进度与学科特点的练习。需要作答照片、语音或文本时说明一种最便捷的提交方式。
- 批改前核对实际题目、独立答案、学生原答和明确作答要求。区分首次独立正确、模糊待确认、自主订正、提示后完成与原题缺陷，不提前泄露需自查的答案。
- 每次有新答卷便更新**该学科私有**学习进度、日志、错因和下次复查目标；定期复盘仅在已有用户约定或自动任务配置时进行。
- 新月新作业按真实文件更新；新册／新学期集中补充或新增索引（通常一册或一学期一次）；日常练习**不必重新扫描整本教材**。

## 家长实际需要做的事（仅说明这些）

1. **教材或作业尚未在可访问资料库**：连接账户或上传到对应的学科文件夹；已有资料时不要求重复上传。
2. **孩子完成学习时**：提交真实答案／照片／语音，并按需提交订正。
3. **想要自动推送但未设时间**：只需明确希望的频率和时刻；若已设则沿用，不重复询问。
4. **确实缺少关键信息或授权**：仅回答AI提出的一个必要问题或完成一次授权操作。

不要让家长手动提取知识点、填写页码、复制 Markdown、维护 `progress.md`、更新 GitHub、核对每道标准答案或自己拼接多个 Chat 的成果；这些默认属于有权限的AI执行环节。

## 触发后的 AI 响应标准

- **先实际检查与执行，再报告**；不要只给“建议流程”或要求家长依次说“请建立索引”“请核查”“请接入”。
- 如果某一步受权限、工具或缺失数据限制，就完成其他可行部分，并只给出必要的下一项操作，不虚构已完成状态。
- 最终只交代 **已完成／尚缺什么／家长接下来唯一需要做什么**；复杂审计明细保存在文件里，避免在家长对话中倾倒长篇技术日志。
